# PROMPT ДЛЯ CODEX — Universal Visual UI Builder

Ты — senior software architect, frontend engineer и разработчик визуальных редакторов уровня Figma, Webflow и FlutterFlow.

Твоя задача — создать полноценное локальное веб-приложение **Universal Visual UI Builder** — мощный визуальный конструктор интерфейсов с экспортом в разные технологии без использования искусственного интеллекта во время работы.

Это не демонстрация, не макет и не статический прототип. Требуется реально работающий редактор с полноценным управлением компонентами, стилями, анимациями, событиями и структурой проекта.

## 1. Главная концепция

Пользователь должен иметь возможность создавать практически любой пользовательский интерфейс мышкой, не написав ни одной строки кода.

Редактор должен поддерживать два режима:

- Free Design — свободное позиционирование элементов, аналогично WinForms Designer и Figma.
- Responsive Design — построение адаптивных интерфейсов с использованием Flexbox, Grid, Auto Layout и ограничений.

В режиме Free Design пользователь может свободно размещать элементы по абсолютным координатам. При экспорте система должна сохранять точную геометрию или преобразовывать её в адаптивную структуру, если это возможно без нарушения дизайна.

Не пытайся автоматически превращать любую произвольную композицию в идеальную адаптивную вёрстку. Если структура неоднозначна, сохраняй абсолютное позиционирование и предоставляй пользователю настройки адаптации.

Используй библиотеки только там, где они действительно нужны. Не создавай лишних зависимостей.

Приложение должно работать локально через npm без обязательного сервера, облачной регистрации или API-ключей.

## 15. Правила разработки

1. Не создавай только красивый интерфейс без функциональности.
2. Не заменяй реальные функции заглушками.
3. Не выдавай частично работающий экспорт за полноценный.
4. Не используй ИИ API.
5. Не требуй платных сервисов.
6. Не удаляй существующий код ради упрощения реализации.
7. Сначала реализуй надёжное ядро, затем расширяй функции.
8. После каждого этапа запускай тесты и проверяй сборку.
9. Документируй реализованные функции и ограничения.
10. Не обещай автоматическую адаптивность там, где невозможно сохранить исходный дизайн без ручных настроек.

## 16. Порядок реализации

Работай по этапам.

**Phase 1 — Core Editor**

Рабочий Canvas, компоненты, выделение, перетаскивание, изменение размеров, инспектор, слои, сохранение.

**Phase 2 — Advanced Styling**

Градиенты, тени, эффекты, типографика, Flexbox, Grid, Design Tokens.

**Phase 3 — Interactions**

Переменные, события, визуальная логика, Preview Mode.

**Phase 4 — Animation Studio**

Timeline, Keyframes, Easing, предпросмотр.

**Phase 5 — Export Engine**

Сначала HTML/CSS/JS, затем React, затем Flutter. Каждый экспортёр должен проходить собственные тесты.

**Phase 6 — Professional Tools**

Пользовательские компоненты, шаблоны, импорт ресурсов, дополнительные инструменты редактирования.

Не пытайся реализовать все этапы одновременно поверх незавершённого ядра.

## 17. Критерии готовности

Программа считается минимально работоспособной, когда пользователь может:

1. Создать новый проект.
2. Добавить несколько компонентов.
3. Свободно переместить и изменить их размеры.
4. Настроить стили и вложенность.
5. Добавить простое событие и анимацию.
6. Запустить интерактивный предпросмотр.
7. Сохранить проект.
8. Перезапустить редактор и восстановить его.
9. Экспортировать работающий HTML-проект.
10. Открыть экспорт в браузере и получить ожидаемый результат.

React и Flutter должны проходить аналогичные проверки перед объявлением соответствующих этапов завершёнными.

Начни с анализа архитектуры, затем создай проект и реализуй Phase 1. После завершения Phase 1 представь список реально работающих функций, результаты тестов и ограничения. Не переходи к следующим этапам, пока основа не работает стабильно.
